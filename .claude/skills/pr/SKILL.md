# /pr — Automated Pull Request Creation

You are in PR MODE. A feature has been reviewed and approved. Your job is to create
a GitHub PR with full context so a human can make the final merge decision.

## Input

`/pr` accepts:
- A review reference: `/pr docs/reviews/auth-oauth2-review.md`
- A branch name: `/pr feat/auth-oauth2`
- Nothing (finds the most recent approved review)

## Pre-Flight

1. Verify the review exists and its verdict is APPROVE
2. Verify the branch exists and has commits ahead of main
3. Verify the branch is pushed to origin (`git push -u origin <branch>` if not)
4. Verify tests pass on the branch (run the project's test suite)
5. Load the spec, run report, and review artifact for context

If any pre-flight fails, STOP and explain what needs to happen first.

## Build the PR Body

Use `gh pr create` with a structured body:

```markdown
## Summary
[2-3 sentences from the spec's Context section — what was built and why]

## Changes
[File-level summary from the run report — files added/modified/deleted with line counts]

## Test Results
- Targeted tests: [X/Y passed]
- Full suite: [X/Y passed]
- New tests added: [count]

## Review Chain
| Reviewer | Verdict | Key Findings |
|----------|---------|-------------|
| Claude (subagent) | PASS | [top finding or "No issues"] |
| Gemini (API) | PASS/FAIL | [top finding or "No issues"] |
| GPT (API) | PASS/FAIL/Skipped | [top finding or "Skipped"] |

**Consensus findings:** [count]
**Review artifact:** `docs/reviews/<feature>-review.md`

## AI Disclosure
- **Planning:** Claude Opus via SpecForge `/spec`
- **Implementation:** [Claude Opus via `/yolo` | Codex via `/forge`]
- **Review:** [list of models used]
- **Spec reference:** `docs/specs/<feature>.md`
- **Human verified:** [Yes — reviewed by user | No — automated pipeline]

## Spec & Artifacts
- Spec: `docs/specs/<feature>.md`
- Run report: `docs/runs/<feature>-run.md`
- Review: `docs/reviews/<feature>-review.md`

---
*Generated by [ReviewForge](https://github.com/benikigai/ReviewForge)*
```

## Create the PR

```bash
gh pr create \
    --base main \
    --head <branch> \
    --title "feat(<scope>): <description from spec>" \
    --body-file /tmp/reviewforge-pr-body.md \
    --label "ai-generated,reviewed" \
    --reviewer <from config or user>
```

Rules for the title:
- Under 70 characters
- Use conventional commit format: `feat(scope): description`
- Match the spec's feature name

## Post-Creation

1. If `DISCORD_WEBHOOK_URL` is set, run:
   ```bash
   bash .claude/scripts/notify-discord.sh \
       --title "PR Ready: <feature>" \
       --url "<pr url>" \
       --score "<review score>" \
       --status "approved"
   ```

2. Print the PR URL for the user
3. Suggest: "Review the PR at [URL]. Merge when ready."

## IMPORTANT RULES

- **Never create a PR without an approved review.** The review is the gate.
- **Never auto-merge.** Create the PR and let humans merge.
- **Always include AI disclosure.** Transparency about how the code was generated.
- **Always link artifacts.** Spec, run report, and review must be referenced.
- **Title under 70 chars.** Details go in the body, not the title.
